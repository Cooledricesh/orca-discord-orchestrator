# Discord에서 운영 변경을 끝까지 처리하기

소유자의 오케스트레이터 수정·운영 적용·재시작 요청에 사용한다. 프라이데이와 오케스트레이터 프로젝트의 마크에게 허용된 운영 절차다. 역할상 작업 폴더 밖 쓰기 금지의 예외는 아래 **운영본의 도구 호출**뿐이다. 토큰·개인 Claude 설정을 직접 편집하지 않는다.

## 요청 처리

- “고쳐줘”, “해결해줘” 같은 운영 장애 수정 요청은 조사·수정·검증·운영 반영·확인까지 포함한다. “검토만”, “수정안만”, “적용하지 마”는 반영하지 않는다. 이미 요청한 범위에 재승인을 요구하지 않는다.
- 프라이데이는 운영 진단에 필요한 오케스트레이터 코드·지침·비밀이 없는 상태를 직접 읽을 수 있다. “시스템 설정이라 권한 없음” 또는 “관리 터미널에서 직접 실행”을 기본 답으로 쓰지 않는다. 실제 OS/인증 오류가 났을 때만 구체적인 막힌 동작을 설명한다.
- 코드 변경은 `$ROUTES_FILE`에서 path가 `$ORCH_ROOT`와 같은 프로젝트로 작업을 넘긴다. 등록되어 있으면 프로젝트를 다시 묻지 않는다. 브리프에 **운영 적용까지 포함**하는지 적는다. 마크가 같은 스레드에서 적용 결과까지 보고한다.
- 프로젝트가 없으면 기존 온보딩 절차로 등록한다. 프라이데이가 임의로 운영 코드를 직접 고치거나 원본 변경을 강제로 덮어쓰지 않는다.

## 코드 변경 → 운영 적용

1. 마크는 자기 worktree에서 수정하고 테스트한다. 실제 변경 파일을 검토해서 명시적으로 add/commit한다. 토큰·routes.json·state·runs는 포함하지 않는다. 자동 생성된 `.claude/settings.json` 변경도 내용을 확인한다.
2. **작업 worktree의 복사본이 아닌** 아래 운영 도구로 계획을 만든다.
   ```sh
   python3 "$ORCH_ROOT/bin/operations.py" plan --thread "<threadId>"
   ```
   운영 저장소·worktree가 깨끗한지, 같은 저장소인지, 최신 운영 HEAD를 포함하는지 확인한다. 오래된 작업이면 자기 worktree에서 최신 운영 브랜치를 병합/리베이스하고 충돌 해결·테스트·커밋한 뒤 다시 계획한다. 운영본의 미커밋 변경을 stash/reset하거나 자동 커밋하지 않는다. 실제 작업 커밋이 없으면 성공으로 보고하지 않는다.
3. 계획의 `files`, `services`, `launchd`, `notes`를 확인한다. 파일별 재시작 추론에 빠진 의존성이 있으면 `--restart 상담역|접수원|리뷰어` 또는 `--launchd sweep|leads-check|접수원-restart|jarvis`를 추가해 새 계획을 만든다. 소유자의 기존 요청 범위이면 적용할 커밋·재시작 대상을 한 줄 알린 후 실행한다.
   ```sh
   python3 "$ORCH_ROOT/bin/operations.py" apply "<id>"
   ```
4. 적용은 분리된 프로세스에서 전체 로컬 검증 → 최신 상태 재확인 → fast-forward 병합 → 의존성 설치 → 지정 launchd 재등록 → 대상 봇 재시작 순서로 진행한다. 프라이데이가 재시작되어도 적용 프로세스는 유지된다. 성공/실패는 원래 스레드에 운영 도구가 보고한다.
5. `status <id>`로 완료를 확인한다. `queued/running`을 완료로 보고하지 않는다. `failed`면 `phase`, `result`, `completed`, `promoted`, `state/operations/<id>/apply.log`를 확인하고 해결한다. 같은 커밋·설정에서 재시도할 때는 `retry <id>`를 쓴다. 커밋/설정이 바뀌었으면 새 계획을 만든다. 재시작만 남았다면 재시작 계획을 만든다. 코드 반영 후 재시작 실패를 전체 미반영이나 성공으로 오해하지 않는다.
6. 성공 보고에 운영 커밋·재시작/재등록 확인과 남은 실제 사용 검증을 구분한다. 실행 중인 마크를 강제로 종료하지 않는다. 작업자 지침·플러그인은 다음 **새 작업**부터 적용된다. 이전 세션 재개는 예전 컨텍스트를 유지한다.

## 코드 변경 없는 운영 작업

프라이데이는 아래 도구를 직접 실행한다. 결과를 받을 현재 Discord chat ID를 `--chat`에 지정한다.

```sh
python3 "$ORCH_ROOT/bin/operations.py" plan --restart 상담역 --chat "<chatId>"
python3 "$ORCH_ROOT/bin/operations.py" plan --restart 접수원 --restart 리뷰어 --chat "<chatId>"
python3 "$ORCH_ROOT/bin/operations.py" plan --launchd sweep --chat "<chatId>"
python3 "$ORCH_ROOT/bin/operations.py" apply "<id>"
python3 "$ORCH_ROOT/bin/operations.py" status
```

launchd 재등록은 기존 설치 경로·환경변수를 보존하고 지정한 job만 반영한다. 등록 실패 시 이전 plist 복원을 시도하고 결과를 기록한다. 실행 중인 sweep/감시 job은 끝난 뒤 retry한다. 미등록 job의 최초 설치, 활성 비전의 세션 변경은 기존 운영 가이드 절차를 확인하여 같은 Discord 요청 안에서 처리한다. 실제 OS 권한/로그인 입력이 필요하면 그 단계만 요청한다.

모델 변경은 기존 `!모델` 경로, 프로젝트 추가/제거는 온보딩 절차를 유지한다. 임의 셸 실행을 받는 새 Discord 명령을 만들지 않는다. 이 도구는 개인 소유자 운영 절차이며 OS 권한 격리 장치는 아니다.
