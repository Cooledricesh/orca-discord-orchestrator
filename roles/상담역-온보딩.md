# 상담역 — 새 프로젝트 온보딩

사용자가 새 프로젝트 추가를 요청하고 이름·위치를 정했을 때 읽는다. 기동 정보의 ORCH_ROOT·ROUTES_FILE을 사용하고, 경로를 셸 인자로 넘길 때는 항상 따옴표로 감싼다.

1. 기존 폴더이면 `git -C "<경로>" status --short`와 `rev-parse --show-toplevel`, `rev-parse --verify HEAD`로 저장소 루트·기준 커밋을 확인한다. 기존 파일을 자동 커밋하지 않는다. 사용자가 새 빈 프로젝트 생성을 요청한 경우에만 폴더·Git 저장소·빈 초기 커밋을 만든다.
2. `orca repo add --path "<절대경로>" --json`으로 등록하고 성공을 확인한다.
3. 사용자가 기존 Discord 채널을 지정했으면 그 ID를 사용한다. 새 채널 생성까지 요청한 경우 상담역의 Manage Channels 권한으로 만든다. 공용 `bin/lib.sh`를 source한 zsh에서 `discord_api "<상담역 봇 이름>" POST "/guilds/<guildId>/channels" "$(cat '<요청 JSON 파일>')"`를 사용한다. 이름·본문은 파일에 작성하고 셸 코드에 보간하지 않는다. 토큰을 직접 읽거나 출력하지 않는다. 권한이 없으면 사용자가 만든 채널 ID를 받는다.
4. ROUTES_FILE을 Python으로 읽어 routes에 `{채널ID: {name, path}}`를 추가하고 임시 파일+replace로 저장한다. 기존 항목을 보존한다. name과 정규화된 path는 다른 프로젝트와 중복되지 않아야 한다. 문서 범위가 필요하면 상대 `writeDir`을 쓴다.
5. `python3 "$ORCH_ROOT/bin/setup.py" doctor`로 설정 오류를 확인한다. 플러그인은 실제 작업 기동 시 `ensure_plugin`이 새 worktree cwd에 project 스코프로 설치한다. `--plugin-dir` 방식으로 바꾸지 않는다.
6. 접수원이 활성화되어 있으면 `"$ORCH_ROOT/bin/leads-check.sh" --restart 접수원`. 리뷰어가 활성화되어 있으면 `"$ORCH_ROOT/bin/jarvis-restart.sh"`. 두 역할 모두 새 라우트를 읽어야 한다.
7. routes.json은 로컬 전용이며 Git에서 제외된다. add/commit하거나 공개하지 않는다.
8. 채널 링크와 첫 작업 안내를 답한다. 새 작업은 원본 HEAD 기준 별도 worktree에서 시작하며, 미커밋 변경은 자동 포함되지 않는다는 점을 필요한 경우 안내한다.

프로젝트 제거는 사용자가 명시적으로 요청할 때 routes 항목 삭제와 관련 데몬 재시작까지만 수행한다. 폴더·채널·결과 worktree 삭제는 별도 요청 범위다.
